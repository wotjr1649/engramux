at main commit `454f6b8b22fd0fc60189a2ec8a76483e717274b6`, passed the ordinary suite and
lint but failed two wall-clock assertions during the race run:

- `TestPostDialBudgetStops`: subprocess 1.3246931 s, less an estimated 14.8771 ms
  startup cost, exceeded the existing 1 s assertion at 1.309816 s. The real input reached

The relay probe contained a separate measurement defect. Empty stdin does not just start and
stop the process: the relay mints an ID and durably spools it. The probe now uses a refused
CLI command, which exits before the relay path. Its regression test asserts that no spool
record was created and that the CLI reported its expected usage error. Replacing it with the
old empty-input probe made that test fail; the restored implementation passed. This correction
does not explain away the original over-budget result or relax the assertion.

The stalled-server test now also records the request-to-observed-close interval and the interval
between observed transport close and subprocess return. These are observations by the parent
test process, not syscall timings: scheduling can delay the observation. The whole-process
assertion, exact spool round trip and 800 ms lower bound remain in place.

The checkpoint test now reports successful checkpoint count, aggregate pool wait count and time,
GC count and stop-the-world pause, and GOMAXPROCS. The 400 committed rows, observed WAL
shrink and 1 s assertion remain unchanged. These diagnostics do not isolate fsync duration.

locally. After the changes, the command actually run was `go test -race -p 1 -count=1
-timeout 2m -run '^Test(SpawnOverheadDoesNotWriteASpool|PostDialBudgetStops|CheckpointingDoesNotBlockIngest)$'
-v ./cmd/engramux ./internal/store`, using the existing local C compiler. Both packages passed.
